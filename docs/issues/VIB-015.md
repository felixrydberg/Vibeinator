# [Feature]: VIB-015 — Refresh summaries before handoff and completion, with fallback

GitHub: https://github.com/felixrydberg/Vibeinator/issues/15

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Ensure pending knowledge is available at the two most important boundaries without making a local-model failure block provider switching.

## Proposed solution

Wire 012 into a cancellable pre-handoff/pre-goal-completion gate. Freeze the source watermark and relevant revisions for packet assembly. On rewrite failure use the previous revisions and a bounded, marked unsummarized excerpt. Record which path was used.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Concurrent user input, summary generation and provider selection changes cannot send a packet for the wrong target or omit unprocessed recent information silently. A failed rewrite neither advances the processed watermark nor erases candidates. The latest user request and provider approval settings survive every fallback.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 012, 014. Estimate: 1–2 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
