# [Feature]: VIB-016 — Expose project/chat summaries and exact handoff context

GitHub: https://github.com/felixrydberg/Vibeinator/issues/16

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/web

## Problem or use case

Make context state understandable and reviewable in the retained interface.

## Proposed solution

Add separate project and chat/goal panels using existing disclosures/panels, typography and localization patterns. Show revision freshness, pending/failed refresh state, sources, and the exact packet/omissions attached to a handoff. Preserve existing provider attribution and conversation scrolling.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Reload restores the same revisions/packet; panels show correct project/chat isolation; keyboard/reduced-motion/accessibility checks pass. UI updates stay within this requested information workflow. Browser screenshots verify the panels alongside streaming and Monaco.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 009, 014. Estimate: 1–3 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
