## Proposed solution

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

A disposable Codex/Claude session completes approve, deny, interrupt, same-provider resume, cross-provider switches and lost-session recovery. Retained old/large payloads are retrieved after pruning/restart; summary failures and Clef outages preserve chat/handoff. An isolated baseline DB upgrades without loss; rollback requires restoring a verified backup when schema incompatibility exists. App identities/update feeds remain separate. No claimed pass relies only on mocks for native behavior.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
