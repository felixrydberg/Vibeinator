# [Feature]: VIB-013 — Build bounded handoff packets from durable information

GitHub: https://github.com/felixrydberg/Vibeinator/issues/13

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Preserve recent intent and useful knowledge with explicit, reproducible limits.

## Proposed solution

Replace excerpt selection with a pure deterministic builder receiving durable summary revisions, objective/status, recent messages, source watermark and actual send allowance. Default to the latest 12 user/agent messages within 24,000 characters, plus summaries capped at 8,000 each; reserve metadata and provider prompt overhead rather than assuming 40,000 characters always fit. Select newest messages before rendering chronologically. Include omission counts and usable history-tool instructions.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

The current request is preserved, recent decisions take priority over older excerpts, Unicode and budgets 0/1/2 are handled, empty/stale summaries have an explicit fallback, and identical inputs produce identical packet hashes. Full source history is never mutated. Cover the 700-character regression from the audit.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 008, 009. Estimate: 1–3 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
