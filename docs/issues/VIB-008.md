# [Feature]: VIB-008 — Add project-scoped history search and exact payload reads

GitHub: https://github.com/felixrydberg/Vibeinator/issues/8

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Any omitted handoff/summary content must actually be discoverable later.

## Proposed solution

Add FTS5 over relevant retained messages/tool text and exact source/payload lookup. Reuse existing stable pagination, thread targeting and capability checks. Include archived chats under an explicit authorized history option; do not expose deleted or other-project data accidentally. Keep sidebar search compatibility separate from the new agent-facing API.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

An agent retrieves an old fact and a complete oversized result after handoff, operational pruning and restart. Every excerpt has source IDs and continuation instructions; default text output is bounded to 12,000 characters including its response envelope. Cross-project IDs/cursors are rejected at the service boundary. Index rebuild/backfill and update/delete behavior are covered.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 004; both adapters for qualification. Estimate: 2–4 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
