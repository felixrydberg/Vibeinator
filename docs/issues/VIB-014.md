# [Feature]: VIB-014 — Integrate immutable packets into existing handoff/recovery

- [x] Searched existing repository issues; no duplicate implementation step found.

## Area

apps/server

## Problem or use case

Use the new context while keeping the existing provider switch behavior and failure controls.

## Proposed solution

Persist the final packet before dispatch, bind it to the same conversation and new provider session, and record accepted/failed/uncertain status through existing delivery/receipt mechanisms. Reuse the same context preparation when native resume is unavailable. Keep active-turn/background-task/approval gates and source selection restoration. Leave deliberate new-thread forks as independent operations rather than silently merging their histories.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Codex -> Claude -> Codex retains one app conversation and starts fresh target sessions. Ordinary same-provider turns send only new input unless native history is unavailable. Failed target start and crashes between prepare/start/send/outcome retain a clear packet/outcome and do not replay tools or blindly resend uncertain input. Inspectable context equals the actual dispatch record, not a switch-time estimate. This milestone can use existing/empty summaries before 012 exists.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 007, 013. Estimate: 2–4 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
