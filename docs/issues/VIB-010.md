- [x] Searched existing repository issues; no duplicate implementation step found.

## Area

apps/server

## Problem or use case

Provide bounded local classification with a safe fallback, without making ordinary chats depend on a running model.

## Proposed solution

Implement `DecisionEngine.decide(state, questions)` against the README's Jev/System One endpoint. Validate question/answer schemas, allowed choices, response size, timeout and cancellation. Configure endpoint/model/optional credential through existing settings and secret storage. Verify the actual installed Ollama/Clef API during qualification rather than treating the README as a runtime test.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Recorded valid/invalid responses, timeout, unavailable model and cancelled request yield typed outcomes. Invalid/uncertain decisions retain information. Credentials never appear in logs/history packets. Clef cannot approve tools, invent operation arguments or mark goals complete.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 003. Estimate: 1–2 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
