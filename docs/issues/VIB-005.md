# [Feature]: VIB-005 — Capture Codex payloads before destructive shaping

- [x] Searched existing repository issues; no duplicate implementation step found.

## Area

apps/server

## Problem or use case

A later hook at `ProviderService` cannot recover data already compacted at Codex ingress.

## Proposed solution

Connect archive acceptance at the native notification/request boundary before `compactCodexNativeEventForIngress`, with bounded queues/backpressure. Preserve native request IDs, session/lifecycle identity, ordering, tools/results and approval decisions without changing authorization or responding twice.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Recorded stream fixtures, unknown events, multi-megabyte tool output, approvals, cancellation and reconnect preserve full supported data and existing normalized UI behavior. Setup/auth secrets follow 003's exclusion policy. Retrying a capture cannot rerun a tool or answer a stale request.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P0. Dependencies: 004. Estimate: 1–3 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
