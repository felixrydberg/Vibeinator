# [Feature]: VIB-007 — Enforce capture failure and projection/replay guarantees

GitHub: https://github.com/felixrydberg/Vibeinator/issues/7

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Adding an archive must preserve persist-before-display while stopping work when required recording cannot continue.

## Proposed solution

Integrate capture acceptance with the supervised pump/dispatch readiness. Introduce bounded archive failure state and stop/interruption behavior rather than merely retrying forever while work proceeds. Keep semantic domain events, previews and raw records linked; avoid making the UI hydrate every raw event.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Disk-full, unavailable database, malformed payload, duplicate delivery and restart tests retain the last committed record, block new dispatch, stop active work and show an actionable failure. Archive retries never duplicate provider execution. Replay reconstructs the same UI; streaming text remains complete while long tool previews stay bounded and point to full content.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P0. Dependencies: 005, 006. Estimate: 2–3 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
