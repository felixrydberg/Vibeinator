# [Feature]: VIB-012 — Rewrite summaries through isolated tools-off provider sessions

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Replace stale facts and resolved blockers with current knowledge while retaining revision evidence.

## Proposed solution

Add a dedicated maintenance operation using the current coding provider/account/model and existing text-generation isolation/process helpers where suitable. Tools-off must be enforced by launch configuration, not just a prompt. Bound inputs/outputs and validate structured source references. Do not alter the native coding session's history or permissions.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

After five completed coding turns with pending retained information, revisions update once. New revisions deduplicate/supersede facts, remove resolved blockers, and stay within the 8,000-character-per-summary cap. Failure/cancellation/invalid sources leave prior revisions and pending candidates intact. Maintenance cannot run tools, count as coding progress, or trigger a goal continuation.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 009, 011. Estimate: 2–4 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
