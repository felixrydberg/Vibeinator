# [Feature]: VIB-002 — Restore state without automatically restarting coding goals

GitHub: https://github.com/felixrydberg/Vibeinator/issues/2

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

The inherited active-goal recovery deliberately starts work on launch; Vibeinator must require resume.

## Proposed solution

Replace goal startup continuation with durable pause while preserving orphaned-turn and pending-request settlement. Characterize and gate ordinary-chat automatic restart, saved quit/resume, queued promotions and usage-limit recovery so they do not start a coding turn contrary to this policy.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Clean quit, crash and kill/restart all leave unfinished turns interrupted and active goals paused. No provider send occurs until user resume/new input. Pending approval cards from dead sessions settle rather than becoming approvals for replacement sessions. Explicit resume continues the same conversation with recovery context.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P0. Dependencies: 001. Estimate: 1–2 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
