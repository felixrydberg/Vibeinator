# [Feature]: VIB-018 — Expose coarse tools over the retained gateway

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Reduce model-facing tool/context overhead without replacing safe existing implementations.

## Proposed solution

Implement `vibe.files`, `vibe.repo`, `vibe.history`, `vibe.browser` as focused facades over existing workspace/Git/history/browser services and the authenticated Agent Gateway. Accept intent plus optional explicit operation and structured arguments. When omitted, Clef chooses only an allowlisted operation; deterministic fallback and clarification cover uncertainty. The caller supplies destinations/arguments.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Results default to 12,000 characters with source IDs and retrievable omissions, full supported captured results are stored, path/symlink/project checks stay authoritative, and browser external effects retain existing approval gates. Invalid routing grants no permissions. Explicit operation works with Clef offline. Keep native-provider tools available and accurately describe that only routed outputs are filterable.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P2. Dependencies: 008, 010, 017. Estimate: 2–4 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
