# [Feature]: VIB-017 — Extend existing goals with evidence and project admission

GitHub: https://github.com/felixrydberg/Vibeinator/issues/17

## Before submitting

- [x] Searched existing repository issues; no duplicate implementation step found.
- [x] Concrete implementation step from the agreed Vibeinator plan.

## Area

apps/server

## Problem or use case

Preserve Synara's goal loop while enforcing Vibeinator's explicit states and completion contract.

## Proposed solution

Keep complete objectives/revisions in SQLite, distinguish paused/blocked/completed, require agent-reported progress/completion evidence, and enforce one active coding turn per project at authoritative admission. Preserve human-input precedence, approval waits, failure pauses and no default turn/time/cost cap. Define no-progress detection using agent reports and deterministic lifecycle signals; Clef does not judge coding correctness.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Two competing chats cannot bypass project coding admission; permit release occurs on interruption/crash/failure; maintenance tasks cannot claim progress. Completion stores evidence and refreshes summaries, blocked differs from user pause, large old objectives remain readable, and restart never silently continues a goal. Preserve existing successful goal timing/queue tests and add focused tests for the stricter product policy.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 002, 003, 007; 015 for final completion path. Estimate: 2–4 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
