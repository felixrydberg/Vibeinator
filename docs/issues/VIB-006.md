## Area

apps/server

## Problem or use case

Claude's normalized/runtime diagnostic representation intentionally strips some original data.

## Proposed solution

Connect capture to the SDK message and permission/input lifecycle before `stripDiagnosticImages` and preview shortening. Keep `canUseTool`, permission modes/settings, account identity, process ownership and session resume unchanged.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Streaming deltas and final snapshots, tool calls/results, approvals/denials, questions, interrupted turns and session restarts retain reconstructable content without duplicating messages. Capture exclusions and attachment handling match 003. Existing permission and process tests remain green.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P0. Dependencies: 004. Estimate: 1–3 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
