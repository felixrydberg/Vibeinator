# [Feature]: VIB-009 — Persist separate project and chat/goal summary revisions

- [x] Searched existing repository issues; no duplicate implementation step found.

## Area

apps/server

## Problem or use case

Project knowledge and a conversation's working state need independent revision history.

## Proposed solution

Add revision/candidate repositories and typed read/update contracts. Keep notes, display snippets and provider-native compaction separate. Implement atomic revision commit with cited durable sources, processed watermark, expected previous revision and per-scope concurrency control.

## Why this matters

Keep complete project context available across restarts and provider handoffs while extending the retained Synara implementation.

## Smallest useful scope

Two chats share project knowledge without overwriting each other's chat state; simultaneous project-summary writers cannot lose updates; failure keeps the previous revision and pending candidates. Rollback, deletion and project relocation have explicit invalidation rules. Empty summaries are valid, allowing 013–014 before classification exists.

## Alternatives considered

Reuse the existing Electron app and provider integrations; a framework migration or provider rewrite is outside this plan.

## Risks or tradeoffs

Priority: P1. Dependencies: 003. Estimate: 1–2 days.

Preserve existing conversation data, approval boundaries and provider lifecycle behavior. Additive schema work must follow the migration contract and include recovery evidence.
