# Implementation tracker

Desktop is the only product. Keep the Electron host, embedded renderer, private backend, contracts, shared utilities and scripts as workspace packages.

The [implementation draft](IMPLEMENTATION-DRAFT.md) defines scope and acceptance. All twenty implementation issues have been created in [felixrydberg/Vibeinator](https://github.com/felixrydberg/Vibeinator/issues?q=is%3Aissue+is%3Aopen). Their local body snapshots are under [issues](issues/); [implementation-issues.json](implementation-issues.json) maps each step to its GitHub number and URL. Each issue carries dependencies, scope and acceptance criteria.

## Delivery workflow

Use one branch per PR, under codex/. A single branch cannot represent several independent stacked PRs. Merge a completed, verified PR before starting its dependent PR; stack branches only when a dependent change must be reviewed before its base merges. Retarget dependent PRs after merging the base.

The [adoption PR #21](https://github.com/felixrydberg/Vibeinator/pull/21), [restart policy PR #22](https://github.com/felixrydberg/Vibeinator/pull/22), [contracts PR #23](https://github.com/felixrydberg/Vibeinator/pull/23), [archive storage PR #24](https://github.com/felixrydberg/Vibeinator/pull/24), [Codex capture PR #25](https://github.com/felixrydberg/Vibeinator/pull/25) and [Claude capture PR #26](https://github.com/felixrydberg/Vibeinator/pull/26) are merged into `main`. Remaining baseline qualification stays under [VIB-001 / #1](https://github.com/felixrydberg/Vibeinator/issues/1). [Capture/replay PR #27](https://github.com/felixrydberg/Vibeinator/pull/27) is also merged. Issue #8 implements [project history search and exact reads](PROJECT-HISTORY.md) on `codex/vib-008-history-search`. The [adoption report](BASELINE-ADOPTION.md) records the baseline build/installer checks and remaining failures. Link every PR to its issue; use “Closes #…” only when all acceptance work is done.
